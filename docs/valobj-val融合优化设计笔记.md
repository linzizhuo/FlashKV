和entry-key的优化不同，valobj-val的优化效果是十分相似的，但valobj-val的优化十分适配当前的项目架构，主要原因有三点！

1. data 和 entry是解耦的，通过指针和虚函数表实现的解耦
2. 不需要为了适配而去更改val-obj的结构，type依旧是那个type，使用方法完全没有变化。

以下是方案：

目前扩容权其实是被分配在val内部的，但其实我们可以打破这层抽象，将扩容权交给上层，即：dict。
和之前的方式一样，编写一个扩容的虚函数，这个虚函数不仅会对底层数据结构进行扩容，还会连带着将type一起拷贝。
缺点是一定程度上破坏了隔离，模糊了职责边界，但我认为这种代价目前完全可以接受！
而且实际的改动也很小——目前只有sds有扩容需求，改动非常小。
